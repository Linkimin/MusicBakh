# 1.0.5 — Library 2.0, итерация E (статические плейлисты) + технический hardening

Пятая итерация многоэтапной работы «Library 2.0». Главное для пользователя — **плейлисты**: четвёртая вкладка, контекстное меню и drag-and-drop. В релиз также входит техническое укрепление по аудиту 2026-09-17 ([`audit-2026-09-17.md`](../audit-2026-09-17.md), [`hardening-2026-09-18.md`](../hardening-2026-09-18.md)). Исправлены дефекты очереди воспроизведения, миграции данных, импорта, поиска и обработки ошибок, а интерфейс стал удобнее на небольших окнах.

## Что нового для пользователя

### Вкладка «Плейлисты»

- В шапке четвёртая вкладка **«Плейлисты»** (`Ctrl+4`). Приложение по-прежнему стартует на «Треки».
- **«+ Новый плейлист»** открывает строку для ввода имени прямо в списке: `Enter` создаёт, `Esc` отменяет. Пустое имя → «Новый плейлист».
- Список отсортирован от новых к старым.
- Клик открывает плейлист: заголовок с числом треков и общей длительностью, **▶ Воспроизвести** и **🔀 Перемешать**, треклист с подсветкой играющего трека. Двойной клик играет трек, `Esc` возвращает к списку.

### Контекстное меню (первое в приложении)

- Правый клик по треку в любом виде (Треки, альбом, исполнитель, плейлист) → **«Добавить в плейлист ▸»**. Если выделено несколько треков, добавляются все.
- В плейлисте — **«Убрать из плейлиста»** для конкретной строки.
- Правый клик по плейлисту → **«Переименовать»** (имя правится прямо в строке) и **«Удалить»** (с подтверждением; треки в библиотеке остаются).

### Drag-and-drop

- Перетащите трек — или несколько, выделенных через `Ctrl`/`Shift`, — на плейлист в списке или в открытый треклист, и они добавятся в конец.
- Перетаскивание внутри плейлиста меняет порядок треков. Порядок сохраняется между запусками.
- Один и тот же трек можно добавить в плейлист несколько раз: каждая копия — отдельная строка со своим местом.

### Воспроизведение плейлиста

- Play/Shuffle и двойной клик наполняют очередь воспроизведения треками плейлиста. Вкладка «Треки» и её фильтры не меняются.
- Фильтры библиотеки к плейлисту не применяются: это ваш ручной набор.

### Плеер стал надёжнее

- **Пауза больше не сбрасывает очередь.** После паузы и возобновления альбом или плейлист продолжаются с того же места. Повторяющиеся треки в очереди (A, A, B) проходятся по порядку, без зацикливания.
- **Управление работает без выделения.** Play/Pause и `Space` управляют текущим воспроизведением, даже если выделение сброшено фильтром.
- Если файл трека пропал, приложение сообщает об этом и не портит очередь играющего трека.
- Длительность больше часа отображается корректно (раньше часы обнулялись).
- Стартовая громкость совпадает с настройками.

### Интерфейс

- Панель управления воспроизведением закреплена внизу окна и не уходит под прокрутку на небольших окнах.
- Шапка и строки компактнее, библиотеке достаётся больше места.
- Редактор выбранного трека подписан отдельно и стал шире: оценка выбранного трека не путается с играющим.
- В карточках треков снова работают двойной клик, подсветка играющего трека и теги во всех видах (после 1.0.4 они молча перестали работать в некоторых списках).
- При пустой выдаче фильтров есть кнопка их сброса.

### Импорт

- Закрытие окна добавления отменяет импорт; недокачанные файлы и обложки удаляются.
- Ссылки на HTML-страницы и повреждённое аудио больше не попадают в библиотеку как «mp3».
- Окно закрывается только после успешной записи в библиотеку. При ошибке можно повторить сохранение без повторного скачивания.

### Поиск

- Совпадения больше не теряются при сочетании поиска с фильтром по жанру или тегам (раньше учитывались только первые 500 результатов).
- Находятся названия вида «A:B» и «A(B)».
- Очень длинный вставленный текст в поле поиска больше не может уронить приложение.

### Ошибки и диагностика

- Сбои диска или базы данных показываются сообщением в строке статуса, приложение не падает. Ошибка записи истории или настроек не прерывает звук.
- При невозможности открыть библиотеку на старте показывается понятное сообщение с путём к данным. Ничего не удаляется и не сбрасывается.
- Появился локальный журнал `%LocalAppData%\MusicLibrary\musicbakh.log` (ротация после 2 МБ). Он нужен только для диагностики и никуда не отправляется.
- При удалении трека удаляется только импортированная копия в папке библиотеки. Исходные файлы вне неё никогда не трогаются.

## Хранение данных

- EF Core миграция **`AddPlaylists`**: таблицы `Playlists` (имя, время создания) и `PlaylistTracks` (плейлист, трек, позиция; каскадное удаление). Применяется автоматически при первом запуске.
- **Перед любой миграцией схемы создаётся резервная копия БД** `library.db.backup-<время>-<id>` (включая WAL). Апгрейд с 1.0.4 проверен на копии реальной пользовательской БД: миграция накатилась, треки, история, теги, настройки и FTS-индекс целы, `integrity_check` проходит.
- Повреждённый legacy-файл `userTracks.json` (апгрейд с 1.0.0) больше не объявляется пустой библиотекой: он остаётся на месте, а запуск сообщает об ошибке.
- Невалидные значения в настройках (громкость NaN, неизвестный режим повтора) заменяются безопасными значениями по умолчанию.

## Внутренние изменения

- `PlaylistsViewModel` — под-VM плейлистов, первый шаг разгрузки `MainViewModel` ([ADR-0002](../adr/0002-extract-playlists-viewmodel.md)). Об изменениях он сообщает событием `PlaylistContentChanged`.
- `IPlaylistRepository` / `SqlitePlaylistRepository` с явными позициями и транзакционными `RemoveAt`/`Reorder`.
- Поведения `DragDropListHelper`, `ReorderMath`, `TrackContextMenuBehavior`, `ContextSelection`, `FocusOnVisibleBehavior` (`MusicLibrary/Behaviors/`).
- Явный индекс позиции в очереди воспроизведения; стратегии повтора больше не ищут трек по первому Id.
- Единый `TrackMapper` вместо четырёх копий маппинга; `DatabaseMaintenance` (бэкап перед миграцией); `StorageErrors` (фильтр ожидаемых ошибок).
- Теги загружаются одним запросом (`ITagRepository.GetTagsByTrack`) вместо запроса на каждый трек.
- Сборка релиза берёт версию из `MusicLibrary.csproj`. CI отделил бенчмарк, ограничивает зависания тестов и проверяет self-contained публикацию.

## Тесты

- **323 теста** проходят + 1 бенчмарк под трейтом `Category=Benchmark`. Из них 279 — после задач плейлистов, ещё 44 — регрессионные тесты hardening. Новые блоки:
  - `SqlitePlaylistRepositoryTests`, `PlaylistsViewModelTests`, `ReorderMathTests`, `ContextSelectionTests`, `DragDropListHelperSelectionTests`.
  - `LeftColumnRenderSmokeTests` — headless-рендер всех шаблонов левой колонки и исполнение реальных WPF-команд (двойной клик в списке, альбоме, плейлисте, истории), геометрия окна 980×640 и 1180×760.
  - `DatabaseMaintenanceTests`, `TrackImporterTests`, `AddTrackViewModelTests`, `MusicBrainzClientTests`, `DurationDisplayTests`, регрессии очереди (A,A,B; пауза/resume; пропавший файл) в `MainViewModelTests`.
- Бенчмарк FTS на 50 000 треков — средний поиск < 100 мс.

## Сознательные ограничения (см. `scope-deviations.md` §1.0.5)

- **Импорт/экспорт `.m3u8`/`.pls`** и **умные плейлисты** — итерация F (`1.0.6`).
- **Обложка-коллаж плейлиста, сортировка и закрепление плейлистов, папки** — нет.
- **«Играть следующим» и редактируемая очередь** — нет (запланировано в `1.3.0` «Audio Engine 2.0»).
- Загрузка библиотеки остаётся синхронной, сетка альбомов не виртуализирована — запланировано на стабилизацию `1.1.0`.
