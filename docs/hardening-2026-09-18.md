# MusicBakh: журнал технического укрепления

Исходный HEAD: `b7c1e80a5319dd4616519813daf19dae5cb70cbe`. Изменения выполнены в рабочем дереве без commit/push/GitHub release. WPF, .NET, SQLite, существующие функции и расположение данных сохранены.

## Существенные изменения

- **Воспроизведение:** позиция очереди учитывает повторяющиеся Id; пауза не пересоздаёт очередь; глобальный транспорт независим от выбора. Отсутствующий файл не портит очередь работающего трека. Проверяются громкость и состояние Open/Play; устаревшие события и lifecycle-подписки отсоединяются. Длительность больше часа отображается корректно.
- **Данные:** повреждённый legacy JSON не объявляется успешно перенесённым; дубли одного пути не импортируются дважды. Перед изменением существующей SQLite-схемы создаётся согласованная backup-копия, включая WAL. Исправлены connection strings с `;` и невалидные настройки. При startup error нет destructive reset.
- **Импорт:** сквозная отмена, дедлайн, проверка формата, очистка собственных промежуточных файлов. Теперь подтверждение включает сохранение в БД: failure → повтор без скачивания или отмена; success → закрытие окна и передача владения. Исходный локальный файл не удаляется.
- **Поиск:** bm25-порядок сохраняется, Id стабилизирует равные оценки; фильтры не теряют результаты после первых 500; ограничен размер входа, исправлены разделители в необычных названиях.
- **Состояние и архитектура:** теги читаются пакетно, фильтрация использует кэш; мутации обновляют агрегаты/детали/очередь. Общий TrackMapper заменяет четыре копии. MainViewModel остаётся крупным — масштабного переписывания не было.
- **Ошибки:** ожидаемые сбои файлов/SQLite не выходят необработанными из основных пользовательских команд. Ошибка истории/настроек не прерывает звук. Локальный ротируемый журнал помогает диагностике; телеметрии нет.
- **UI:** компактная шапка и строки, пустая выдача с очисткой фильтров, закреплённый транспорт. Центральный редактор 360 DIP с читаемым описанием и закреплёнными действиями. Выбор и воспроизведение визуально различаются. Исправлены реальные команды double-click, подсветка и теги в шаблоне списка.
- **Сборка:** версия release script берётся из csproj; проверяется наличие shipped Music/Covers; исправлена ссылка установщика; CI отделяет benchmark, ограничивает зависания и проверяет self-contained publication.

### Исправленный побочный эффект UI-тестирования

При расширении старого render harness выяснилось, что WPF ставит OnStartup в очередь даже без Application.Run. Один диагностический прогон запустил production startup; SQL-журнал показал обновление путей трёх встроенных треков на тестовый output. Удаления записей/файлов в этом прогоне не выполнялись. Эти пути штатный BuiltInTrackSeeder обновляет при следующем обычном запуске. Ошибка изоляции устранена: внутренний App(startServices:false) загружает настоящие XAML-ресурсы, но не запускает host, миграции или пользовательское хранилище. Последующие render-прогоны используют только этот режим.

## Оставшиеся ограничения

Реальный звук на разных устройствах, длительное воспроизведение, native DPI между мониторами и установка/обновление/удаление на чистой Windows не проверены. Установщик собран, но не опубликован и не установлен поверх пользовательской версии.

Полный UI-путь на 50k с большими обложками ещё нуждается в профилировании: часть работы синхронна, сетки альбомов без виртуализации, общий cover decode не ограничен. Сохранение громкости пока синхронное. Эти ограничения не скрываются за быстрым SQL benchmark.

Исходная оценка готовности к широкой аудитории — около 6/10; после исправлений — около 7,5/10. Рекомендуемый следующий этап перед публичным релизом — натурная проверка Windows/audio/upgrade и измерение крупной библиотеки, затем отдельное решение о номере и публикации версии.
